This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

ServerHub — a web UI for managing remote Linux servers over SSH. Features: SSH terminal (xterm.js + WebSocket), SFTP file browser, and command presets (a one-click command runner). Monolith: one Express backend + WebSocket server, one Vite/React frontend. All UI copy and code comments are in **Chinese** — keep them in Chinese.

## Architecture

- `server/index.js` — Express + WebSocket (`ws`, path `/ws/terminal`) on port 3120. All REST `/api/*` routes read/write the JSON files in `data/` directly. Static `dist/` served when present; `app.get('*', ...)` is the SPA fallback.
  - Upload (`POST /api/servers/:id/files/upload?path=&name=`) streams the raw request body → `sftp.createWriteStream` (no multer, constant memory, large-file safe). Completion is signalled by the write stream's `'close'` (ssh2 `'finish'` is unreliable on Node 18+), then the route `sftp.stat`s the remote file and **verifies its size equals the request `Content-Length`** — because SFTP has no end-to-end byte reconciliation, a server that silently writes fewer bytes would otherwise produce a false-success smaller file. On any error or size mismatch the partial remote file is deleted (`deletePath`) and a 4xx/5xx returned. Download route stats first to set `Content-Length` (progress). Delete (`DELETE /api/servers/:id/files?path=&recursive=`) is recursive by default.
  - Commands are scoped: `?serverId=` on `GET /api/commands` returns 公共 (serverId absent/`'common'`) + that server's own. `data/commands.json` gains optional `serverId`.
- `server/ssh-manager.js` — plain JS (ESM, `"type": "module"`). Holds live SSH connections in-memory:
  - `connections`: `Map<serverId, { client, status, shells: Set }>`
  - `connecting`: `Map<serverId, Promise>` for dedup while a connect is in flight.
  - One ssh2 `Client` per server id; on `close`/`end` it closes all tracked shells, clears from both Maps, and deletes the connection (no reconnect handling).
  - `connect()` auto-creates `data/` and JSON files (with 18 default commands, `[]` for servers/sessions) if missing (side effect at module load).
  - `execCommand` has a 30s timeout and 5MB output cap; file preview is capped at 512KB; on SFTP `readdir` failure it falls back to `ls -la` output (`raw` + `note` fields).
  - `createShell(serverId, sessionId?)` tags the stream with `stream.sessionId`; `destroyShell(serverId, sessionId)` closes a specific session's shell (used by session DELETE). `retryAfterReconnect(serverId, fn)` auto-heals sshd `MaxSessions` channel exhaustion (reconnect once on "Channel open failure"). Shells are closed via `disconnect()`, by WS close, or when the remote shell exits.
  - SFTP helpers: `createUploadStream(serverId, remotePath)` → `{ writeStream, sftp }` (sftp is exposed so the upload route can `stat` the remote size for the integrity check); `deletePath(serverId, remotePath, { recursive })` recursively removes dirs (does not follow symlinks — unlinks the link itself). Bookmarks in `data/bookmarks.json` via `readBookmarks/writeBookmarks`.
  - Key exports: `readServers/writeServers/readCommands/writeCommands/readSessions/writeSessions/readBookmarks/writeBookmarks`, `connect/disconnect/getConnectionStatus/getClient`, `createShell/destroyShell`, `execCommand`, `listDirectory`, `readFileContent`, `createUploadStream`, `deletePath`, `retryAfterReconnect`, `connections`.
  - **独立文件连接 (fileConnections)**: SFTP file ops (`listDirectory`/`readFileContent`/`createUploadStream`/`deletePath` and the `/files/local-to-remote` + `/files/remote-to-local` transfer routes) run on a **separate ssh2 connection** (`fileConnections` map; `ensureFileClient`/`getFileClient`/`disconnectFile`/`retryFileAfterReconnect`, config reused via `getServerConfig`), NOT on the terminal `connections`. This is deliberate: terminal shells and SFTP used to share one connection, so repeated transfers exhausted sshd `MaxSessions` and `retryAfterReconnect`'s `disconnect(serverId)` killed **all** terminal shells ("上传下载后切回会话就中断"). Now file channels never consume the terminal connection's budget, and `retryFileAfterReconnect` only reconnects the file connection — terminal sessions stay stable no matter how many files you transfer. **Additionally `getFileSftp(serverId)` reuses ONE sftp session per file connection** (each `client.sftp()` call would open a new SFTP channel; rapid navigation/transfers would accumulate until MaxSessions and throw "(SSH) Channel open failure"). sftp/connection caches are cleared together on close/end/disconnect.
- `src/main.tsx` → `App.tsx` → `components/`: `Sidebar`, `ServerModal`, `Terminal`, `FileBrowser`, `SessionTabs`, `CommandPanel`, `TransferBar`, `ConfirmDialog`. Shared types + category labels/colors + `MAX_SESSIONS_PER_SERVER` in `src/types.ts`.
- **Transfers survive tab/server switches**: `src/lib/TransferStore.ts` is module-level (a `Map` of transfers + `useSyncExternalStore` hook). Uploads use XHR (`xhr.upload.onprogress`), downloads use `fetch` + `ReadableStream` with `Content-Length` progress. The controller (abort) lives in the store, NOT in component state, so switching tabs/servers does not abort in-flight operations. `TransferBar` (always mounted at the bottom of the main column) renders them.
- **Commands run in the terminal**: `src/lib/TerminalBridge.ts` is a module registry `sessionId → sendInput` (also `sendInput`/exporter/focus registries). `Terminal`/`LocalTerminal` register when their WS reaches `connected` and unregister on close/unmount. `CommandPanel` (collapsible, mounted in the terminal layer) shows 公共 + 本服务器 command sets grouped by category; clicking sends `cmd.command + '\r'` to the active session AND calls `focusTerminal(sessionId)` (TerminalBridge focus registry → `term.focus()`) so the user can type immediately without re-clicking the terminal, falling back to `POST /execute` + toast if no terminal is ready. Command panel supports checkbox **batch delete**, **delete a whole command set** (one category), create a **new command set** (new category) in the modal, and **drag & drop** a command to another set/partition (native HTML5 DnD → `PUT /api/commands/:id` with new `category`+`serverId`). `PUT /api/commands/:id` accepts `serverId` (null/'common' → common, stored without the field).
- **Multi-session terminals**: each server can have up to `MAX_SESSIONS_PER_SERVER=8` sessions (sshd `MaxSessions` per-connection limit). A session = a `data/sessions.json` record (name persisted) + one WS `/ws/terminal?serverId=&session=` connection + one remote shell. `App.tsx` keeps **all** sessions' `<Terminal>` mounted in a hidden absolute layer (CSS `display:none`) so switching servers/tabs does NOT tear down WS/shells — switching is just visibility toggling + refit. **The whole remote workspace stays mounted even when `sidebarView==='local'`** (local view is an `absolute inset-0` overlay on top; the remote workspace only gets CSS `hidden`) — without this, switching to 本地 would unmount every remote `<Terminal>`, closing WS/shells and killing running remote tasks. Terminal has a **bounded** auto-reconnect (max 3 attempts, 1s/2s/3s, reset on `connected`). Must NOT put `connected`/`connecting` in the WS effect deps (that was the cause of an infinite reconnect/freeze bug). Terminal accumulates all received output in `fullContentRef` (via a `TextDecoder`) and registers it with `TerminalBridge` (`registerTerminalExporter`/`getTerminalContent`) for the **right-click → 导出会话内容(txt)** menu item (`SessionTabs` `onExportSession` → `App.handleExportSession` strips ANSI codes and downloads a Blob, unlimited size). Terminal's `fit()` is wrapped in `fitPreserving()` and data writes smart-scroll back to bottom (only when the viewport was already at the bottom) to avoid xterm jumping the view to the top after Enter/output. **滚动缓冲 vs 全量历史**: xterm `scrollback` has NO hard API cap but is RAM-bound (~1.5–2MB per ~1000 lines at ~200 cols, so millions of lines eat GBs and freeze), so Plan C keeps the live buffer at `scrollback: 200000` and guarantees real 全量 via `FullHistoryViewer.tsx` — a virtualized (only visible rows rendered) modal fed by `fullContentRef` (all bytes since connect, unaffected by scrollback), opened by the **查看完整历史** button in each terminal's top-right status bar (`Terminal.tsx` and `LocalTerminal.tsx`; LocalTerminal accumulates its own `fullContentRef` now).
- **Session tab reorder** (`SessionTabs`, `onReorder`): same-server tabs are HTML5 draggable; dropping computes the new id order and calls `POST /api/servers/:id/sessions/order`. `App.tsx`'s `handleReorderSessions` reorders local state in place (keeps positions of other servers) then persists.
- **Background-output badge**: `Terminal` calls `onActivity(sessionId)` on WS `data` when its tab is **not** active (via an `activeRef` — the WS effect deps deliberately exclude `active`, so a stale-closure ref is used). App tracks `busySessions: Record<sessionId, boolean>`, clears it when a session is selected, and shows a pulsing red dot on that session's tab (`SessionTabs`) and sidebar row (`Sidebar`).
- Every server row in `Sidebar` has a dedicated one-click **新建会话** `+` button next to the settings gear — no need to open the gear menu. Each server's session row in `SessionTabs` also ends with a `+` create button.
- Copy/paste in Terminal: left-click selection auto-copies via `navigator.clipboard.writeText`; right-click pastes via `readText` → `term.paste()`. Requires a secure context (`localhost`/https) — clipboard API is silently blocked over plain `http://IP`.
- Dev wiring: Vite proxies `/api` and `/ws` (with `ws: true`) to `http://localhost:3120` (`vite.config.ts`).
- **本地终端 (local Windows PowerShell terminal)**: `server/local-exec.js` spawns a **node-pty ConPTY** `powershell.exe` per local session (module-level `localShells` Map, `createLocalShell/getLocalShell/destroyLocalShell/resizeLocalShell`, plus `readLocalDirs/writeLocalDirs` for `data/local-dirs.json` and `browseDirectory()` for listing dirs/drives). Only ONE WebSocketServer (`wss`) serves both `/ws/terminal` and `/ws/local` — `server/index.js` branches on `url.pathname` (a second `WebSocketServer` on the same HTTP server returned HTTP 400, so don't add another one). The local WS reuses the exact terminal protocol (base64 data/input/resize/connected/error), and the shell exits when the WS closes.
  - `node-pty` ships **N-API prebuilds** (`prebuilds/win32-x64/pty.node`), so NO native rebuild is needed even in Electron (N-API is ABI-stable); do NOT run `electron-rebuild` on it (no VS toolchain → fails). electron-builder needs `build.asarUnpack: ["node_modules/node-pty/**"]` (set in package.json) so the `.node`/`winpty-agent.exe`/`winpty.dll` are unpacked from asar.
  - Frontend: `src/components/LocalTerminal.tsx` mirrors `Terminal.tsx` but hits `/ws/local?session=<id>&cwd=<cwd>` with no server-connect prerequisite, registering into `TerminalBridge` by its id. A separate local tab strip + persistent hidden layer lives in `App.tsx`. **The local workspace is ALWAYS mounted** (an `absolute inset-0` overlay, CSS `hidden` when not in local view), symmetric with the remote workspace, so switching 远程↔本地 never unmounts the local `<LocalTerminal>`s / kills their node-pty shells. Local tabs are HTML5-draggable to reorder (in-memory `localSessions` state) and each has a copy-path button; selecting a session auto-syncs the sidebar dir to its `cwd`.
  - **DeviceFilePanel** (`src/components/DeviceFilePanel.tsx`): in the 本机 view a hdc-device file panel sits between the left sidebar and the terminal (`App.tsx` local workspace), with a draggable divider (width persisted in `localStorage` `serverhub:devicePanelWidth`). Browsing uses `GET /api/local/hdc-list` (`hdc file list`); local file dragged in = upload (`hdc-send`), its file dragged to the local panel = download (`hdc-recv`). `LocalDirBrowser.tsx` (sidebar; shows files AND dirs, draggable divider between dir list and favorites, plus button upload/download modals that remember the last device/local path via `/api/local/transfer-state`) is both a drag-source (kind `'local'`) and a drop-target (kind `'device'`/`'server'`).
  - `RemoteLocalPanel.tsx`: the remote 文件 (`FileBrowser`) view gained a toggleable (`Computer` toolbar button) Windows-local dir panel (favoritable, via `/api/local/favorites`) on its left with a draggable divider (persisted `serverhub:localPanelWidth`); drag local file → remote list = upload (SFTP), drag remote file → local panel = download, via the two SSE-free streaming routes below. All cross-pane drags share `DND_MIME = 'application/x-serverhub-file'` (JSON `{kind:'local'|'device'|'server', path, name, isDir}`) defined in `DeviceFilePanel.tsx`. **批量双向传输**: RemoteLocalPanel has a `Square/CheckSquare` select-mode toggle → check local files → "上传选中到远程(N)" (to `FileBrowser`'s `remoteDir`); FileBrowser shows a checkbox column on remote rows when the local panel is open (click to toggle, `selRemote`) → toolbar "下载选中到本机(N)" (to `RemoteLocalPanel`'s current dir via `onPathChange` → `localPanelPath`).
  - The local sidebar view (`LocalView` in `Sidebar.tsx`) has 目录/命令 sub-tabs (dirs shown separate from commands, not stacked); no session list in the sidebar (sessions are closed from the top tab strip). `CommandPanel.tsx` gets `localMode`/`activeLocalSessionId` — commands are split into **two non-shared sets**: remote (default/`scope` absent) and local-terminal (`scope:'local'`); `?scope=local` fetches the local set.
- **Electron desktop shell** (`electron/main.cjs` + `electron/preload.cjs`, plain CJS): in production it dynamically imports `server/index.js` on port 33120 (localserver) and loads its UI; in dev (`ELECTRON_START_URL` set) it skips the backend and loads Vite directly. `contextIsolation` on, `nodeIntegration` off; the preload exposes only `window.serverhub.saveFile/openFile` IPC for the command 导入/导出 native dialogs (remembers last dir in `userData/ui-prefs.json`). `electron-builder` config lives in `package.json` (`build` key → `release/`).

## API surface (REST)

- Servers: `GET/POST /api/servers`, `PUT/DELETE /api/servers/:id`, `GET /api/servers/status`, `GET /api/servers/:id/status`, `POST /api/servers/:id/connect|disconnect|execute`.
  - `GET /api/servers` returns passwords masked as `••••••••`. `PUT` refuses to overwrite password when the incoming value starts with `••`.
  - `/execute` bodies: `{ command }`. Auto-connects if not connected.
- Files: `GET /api/servers/:id/files?path=`, `GET /api/servers/:id/files/content?path=` (512KB preview cap), `GET /api/servers/:id/files/download?path=` (streams binary, sets `Content-Length`, does NOT go through JSON), `POST /api/servers/:id/files/upload?path=<dir>&name=<file>` (raw body stream → remote write), `DELETE /api/servers/:id/files?path=` (recursive dir delete). All auto-connect. **`GET /files` and `/files/content` use the dedicated file connection** (`ensureFileClient` + `retryFileAfterReconnect`), NOT the terminal `retryAfterReconnect` — so directory browsing/exhaustion can never `disconnect` terminal sessions (this was a leftover bug caught by the stress test).
  - Remote ↔ 本机(Windows) file transfer (backend runs on the local Windows box, so it touches both SFTP and the local FS): `POST /api/servers/:id/files/local-to-remote` `{localPath, remoteDir}` (local fs read stream → SFTP write), `POST /api/servers/:id/files/remote-to-local` `{remotePath, localDir}` (SFTP read → local fs write; creates `localDir`; `createWriteStream` overwrites an existing same-named local file; the SFTP read-stream creation is wrapped in `retryAfterReconnect` so repeated drag transfers that exhaust sshd `MaxSessions` channels ("channel open failure") auto-reconnect). Drive the `RemoteLocalPanel`/`FileBrowser` drag cross-transfer.
- Bookmarks (per server, persisted): `GET/POST /api/servers/:id/bookmarks` (POST `{ path, name? }`, dedupes by serverId+path), `DELETE /api/servers/:id/bookmarks/:bid`.
- Commands: `GET /api/commands?serverId=` (scope filter; no param = all), `POST /api/commands` (optional `serverId`), `PUT/DELETE /api/commands/:id`.
- Sessions (per server; persists names only): `GET/POST /api/servers/:id/sessions`, `PUT/DELETE /api/servers/:id/sessions/:sessionId`, `POST /api/servers/:id/sessions/order` (body `{ ids: [] }` — reorders that server's sessions, keeps other servers in place), `POST .../sessions/:sessionId/duplicate` (new session keeps name + current cwd). POST with `{ name? }` defaults to `会话 N`. DELETE calls `destroyShell` server-side.
- Local dir/favorites (本机, for local terminal): `GET /api/local/browse?path=` → `{ entries:[{name,isDir,size}], note }` (empty path = drive letters; `size` = bytes for files, `0` for dirs), `GET /api/local/default-dir` → `{ path }`, `POST /api/local/open-dir` `{path}` → opens the dir in Windows Explorer (`openLocalDir` → `spawn('explorer.exe',[path])` in `local-exec.js`; button in **both** `RemoteLocalPanel` and `LocalDirBrowser`), `GET/POST /api/local/favorites` (POST `{ path, name? }`, dedupes by path), `DELETE /api/local/favorites/:id`. Persisted to `data/local-dirs.json`.
- **File-size display with unit** (`src/lib/sizeFormat.ts`): `browseDirectory` and `hdcFileList` return per-file `size` (bytes). `RemoteLocalPanel`, `LocalDirBrowser`, and `DeviceFilePanel` show the size on file rows and each has a `B/ KB/ MB/ GB` unit selector (default bytes; persisted to `localStorage` `serverhub:sizeUnit`) via `getSizeUnit/setSizeUnit/formatSize`.
- **hdc device transfer** (本机 ↔ hdc 连接设备): `POST /api/local/hdc-send` `{localPath, devicePath, serial?}` / `POST /api/local/hdc-recv` `{devicePath, localDir, serial?}` run `hdc file send|recv` host commands (via `runHostCommand` in `local-exec.js`, 60s timeout); `GET /api/local/hdc-list?path=&serial=` lists a device directory via `hdc [-t serial] shell ls -la <path>` (this hdc version has NO `file list` subcommand — only `file send/recv`), then parses ls -l output into `{name,isDir}` (skipping `total`/error lines and `.`/`..`); `GET /api/local/hdc-targets` runs `hdc list targets` → `{targets:[{serial,state}]}`; `GET/POST /api/local/transfer-state` persists the last used device/local path to `data/local-transfer.json` (so the UI pre-fills it).
  - **多设备支持**: connected devices are listed via `hdc list targets` and selectable in the 设备文件 panel header; every hdc file command prepends `-t <serial>` (via `targetArgs` in `local-exec.js`) when a serial is chosen.
  - **连接/断开由后端维护**(不依赖本地终端): `GET /api/local/hdc-state` / `POST /api/local/hdc-connect` `{serial}` / `POST /api/local/hdc-disconnect` set the module-level `deviceConn {connected, serial}` in `local-exec.js` (`getDeviceState/connectDevice/disconnectDevice`). The 设备文件 panel header's **连接设备 / 断开设备** toggle button calls these directly, and reloads the device directory on connect.
  - **本地终端界面有一键开关设备目录栏按钮**(`App.tsx` 顶部栏, `Smartphone`): toggles `devicePanelOpen` state (persisted `serverhub:devicePanelOpen`), conditionally rendering `<DeviceFilePanel>` + the draggable divider (persisted `serverhub:devicePanelWidth`).

Ids are generated server-side as `srv-<timestamp>` / `cmd-<timestamp>` / `ses-<timestamp>` / `bm-<timestamp>`.

## WebSocket terminal protocol (`/ws/terminal?serverId=...&session=<sessionId>` and `/ws/local?session=<id>&cwd=<dir>`)

All WS messages are JSON strings. Terminal data bytes are **base64-encoded in both directions**. Message `type`s:
- Server → client: `connected`, `error` (with `message`), `data` (base64, SSH shell stdout).
- Client → server: `input` (base64), `resize` (`{ rows, cols }`).
The `session` query param is optional (used to tag the shell for `destroyShell`). On WS close the shell is closed; conversely when the shell stream closes (`exit` typed, destroyed, or remote end), the server also closes the WS, so there are no orphaned connections. The underlying SSH connection stays alive (cache) until `disconnect()`.

## Data & security gotchas

- `data/servers.json` stores **passwords in plaintext** — `GET /api/servers` masks them, but the file itself is not encrypted. Meant for local/intranet use.
- Data dir is `data/` by default but overridable via `SERVERHUB_DATA_DIR` env; Electron sets it to `app.getPath('userData')` (asar is read-only, so production data goes to `%APPDATA%/ServerHub`) and also sets `PORT` to 33120. Don't hardcode the `data/` path — resolve it as `ssh-manager.js` does.
- SSH connect: `readyTimeout: 15000`, `keepaliveInterval: 30000`; default port 22 if omitted. Optional `privateKey` on a server disables password auth.
- Terminal `data` and `input` MUST be base64 or the protocol breaks (UTF-8/control chars corrupt over JSON).
- Raw binary (e.g. downloads) never travels through the JSON/exec endpoints — always use the streamed `/files/download` route.
